# Phase 4 — MCP server and chat interface
#
# T-63: fastmcp and the official `mcp` SDK it wraps do NOT pin an upper bound
# on starlette, so an unpinned `pip install fastmcp` drags in the newest
# starlette (1.6.0+), which breaks FastAPI 0.111.0 outright (a Router
# constructor argument FastAPI relies on no longer exists) and breaks
# OpenTelemetry's FastAPI instrumentation the same way. Pinning `starlette`
# itself back down to the version Phase 1 already needs is enough — mcp
# 1.6.0's own requirement is only a lower bound, so the old pin still
# satisfies it. Verified: all of Phase 1, 2 and 3's tests still pass with
# this exact combination installed.
# ---------------------------------------------------------------------------
mcp==1.6.0
fastmcp==0.4.1
starlette==0.37.2               # keep pinned here too: nothing above may raise this
